## 配置区（文件顶部，都在一个地方）

| 参数 | 默认 | 作用 |
| :--- | :--- | :--- |
| `ALL_COLORS` | `True` | **三种颜色都检测**；改成 `False` 只测 `TARGET_COLOR` 那一种 |
| `TARGET_COLOR` | `1` | 只在 `ALL_COLORS=False` 时生效：1 红 / 2 绿 / 3 蓝 |
| `PRINT_ONLY_DETECTED` | `True` | **只打印检到的球**；全场无球时才打一行 `未找到任何小球(红/绿/蓝)`。设 `False` 则每种颜色各自打印（含"未找到X球"，调单色阈值时用） |
| `COLOR_LAB` | v1 的三组 | 三色阈值（LAB），换灯光要重标 |
| `MIN_AREA` | `100` | 小于这么多像素的色块丢掉 |
| `ASPECT_MIN/MAX` | `0.70 / 1.40` | 长宽比范围：球近似圆，太扁太细的不要 |
| `FILL_MIN/MAX` | `0.50 / 0.92` | 饱满度 = 像素数/(w×h)：圆约 0.785，实心方块≈1.0 会被卡掉 |
| **`CALIB_WIDTH_PX`** | **`{1:0, 2:0, 3:0}`** | ★**距离标定值（按颜色分开）**：该颜色球放 10cm 处读到的 w；填了才启用该颜色的距离过滤 |
| `CALIB_DISTANCE_CM` | `10.0` | 标定时球放的距离 |
| `DIST_MIN_CM / DIST_MAX_CM` | `5 / 15` | 只接受这个距离范围内的球（把"后面的东西"排掉） |
| `PRINT_MOVE_PX` | `20` | 中心移动超过多少像素才再打一行 |
| `PRINT_MIN_INTERVAL_MS` | `1000` | 位移打印的最小间隔（兜底限流）；**丢球/检到不受此限** |
| `SHOW_REJECT` | `False` | 设 `True` 会把被过滤掉的候选及原因打出来（调阈值/过滤参数时非常有用） |
| `DRAW` | `True` | 是否画框 + 写数字标签 |
| `DRAW_DEBUG` | `False` | **屏幕上没有框时打开它**：把 `draw_rect` / `draw_string` / `display.show` 的报错打出来（默认静默，曾经因此查不出问题） |
| `DRAW_SELFTEST` | `False` | 启动后前 2 秒在画面正中画一个 `DRAW TEST` 框：**能看见 = 画图 API 正常，问题在"没检测到球"**；看不见 = 画图/显示有问题 |
| `RECT_COLOR_RGB` | — | 兜底颜色；框色优先用 `image.COLOR_RED/COLOR_GREEN/COLOR_BLUE` 常量（最兼容） |

### 屏幕上没有框？按这个顺序查

1. 先把 **`DRAW_DEBUG = True`** → 再看终端有没有 `[错误] draw_rect 失败: ...`
   * 有报错 → 就是画图 API 的参数问题，把报错原文发我
   * 没有报错 → 说明**根本没检到球**（画框只在检到球时才画），去看终端有没有 `红(1) x=..` 那种行
2. 再把 **`DRAW_SELFTEST = True`** → 启动后 2 秒内画面正中应该出现一个 `DRAW TEST` 框
   * 测试框能看见 → 画图没问题，是识别/过滤把球筛掉了 → 打开 `SHOW_REJECT = True` 看被过滤的原因
   * 测试框也看不见 → `display` 或画图 API 有问题，把 `DRAW_DEBUG` 的报错发我

```

连续识别中...
[  1.20s] 红(1) x=300 y=140 w=60 h=60          ← 红球进画面
[  2.05s] 绿(2) x=120 y=160 w=58 h=57          ← 绿球进画面
[  2.41s] 红(1) x=330 y=150 w=62 h=58  距离≈9.7cm   ← 标定后带上距离
[  3.02s] 未找到任何小球(红/绿/蓝)              ← 都移走了, 打一行就安静
```

**只打印检到的颜色**，不会为"没检到的颜色"各刷一行。想变成逐色打印（调单色阈值时有用）：
把 `PRINT_ONLY_DETECTED` 改成 `False`。

### 距离限定怎么用（第二轮新增）

原理：球在画面里的宽度 `w` 与距离 `d` 成反比 → **`d = K / w`**，`K = 标定距离 × 标定宽度`。
标定值会把球的真实直径"吸收"进去，所以**你用什么大小的球都不影响**，只要做一次标定：

1. 代码里 `CALIB_WIDTH_PX` 先保持 `0`（未标定状态）→ 此时**不启用距离过滤**，只打印 `w`。
2. 把球放在 **10cm** 处，读终端打印的 `w=??`。
3. 把这个数字填进 `CALIB_WIDTH_PX`（或告诉我，我帮你填）。
4. 之后每行会打印 `距离≈9.7cm`，并**只接受 5~15cm 的球**；超出范围会打印
   `(最近候选 20.0cm, 超出 5~15cm)`，一眼看出是"没识别到"还是"太远被排掉"。

> 距离不会很精确（像素宽度本身有 ±1~2px 抖动），但用来"排掉后面的东西"完全够。
> 需要更准就把 `DIST_MIN/MAX` 收紧，或把球放的标准距离改大（标定距离越远，同样像素误差换算出的距离误差越小）。

### 屏幕上写的是什么

标签是**纯数字形式**（与将来发给 STM32 的串口 body 字段顺序一致）：

```
1 x300 y140 w60 h60        ← 颜色编号 x y w h
```

之所以不用中文：MaixPy **默认字体只支持英文**，写中文会显示成问号（你之前看到的三个问号就是这个原因）。
如果以后想在屏幕上显示中文，可以加载系统内置思源黑体：

```python
image.load_font("cn", "/maixapp/share/font/SourceHanSansCN-Regular.otf", size=20)
image.set_default_font("cn")
```

### 调参提示

* **球找不到** → 阈值太窄（或 `MIN_AREA` 太大）→ 可加一个"打印 LAB 值"的标定模式（见 `DEV_LOG.md` 第 5 问，改动很小）
* **满屏误识别** → 阈值太宽 → 先开 `SHOW_REJECT=True` 看混进来的是什么
* **忽有忽无** → `FILL_MIN` 偏紧（反光/遮挡让填充率下降）→ 降到 0.40 试试
* **近处的球被判太远** → `CALIB_WIDTH_PX` 标定值不准，重新标一次

## 附：v1（串口协议版）的接线与标定要点

v1 是将来和 STM32 联调时用的，接线与阈值标定要点如下（完整内容见 `backup/README_v1.md`）：

* **UART0（默认）**：A16 = TX → STM32 PA3，A17 = RX ← STM32 PA2，GND 共地；设备节点 `/dev/ttyS0`
  * ⚠ 官方提醒：UART0 是系统日志口（上电会吐启动日志，v1 的帧解析器会自动跳过垃圾字节），
    且 A16(TX) 兼作启动模式脚、**上电时不能被拉低**。
* **UART1（官方推荐用于自定义通讯）**：A19 = TX / A18 = RX / `/dev/ttyS1`，v1 会自动做 pinmap。
* 两端统一 **115200 8N1**（MaixCAM 只验证过 115200，别用别的波特率）。
* 颜色 LAB 阈值、白色灰度阈值、形状判别像素差都**必须现场重标**。
