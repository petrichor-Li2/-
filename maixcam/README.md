# MaixCAM-Pro 视觉模块说明（交付版 v3）

> 这是交给队友的视觉模块。**只有一份文件**：`main.py`，既能跑协议，也能现场标定。
> 需求确认过程见 `DEV_LOG.md`；v1（更早的纯协议版）备份在 `backup/`。

## 一、文件清单

| 文件 | 用途 |
| :--- | :--- |
| **`main.py`** | ★ **交付版**：跑协议（接单片机）+ 标定（读 LAB）+ 屏幕画框，一份搞定 |
| `ball_test.py` | 单色球调试工具（纯打印，不回协议帧）——只想盯一个球时用 |
| `tested.py` | 形状识别的早期调试脚本（保留作参考，里面的 `get_pixel` 用法已合并进 main.py） |
| `backup/` | v1（纯协议版）备份 + 说明，含 SHA256 |

## 二、三种运行状态（改 `main.py` 顶部一个词）

| `MODE` | 什么时候用 | 表现 |
| :--- | :--- | :--- |
| **`"both"`**（默认） | 联调：一边看终端一边看单片机 | 回应单片机命令 **同时** 每秒打印 LAB |
| `"protocol"` | 比赛：最干净最快 | 只回应单片机命令，**不打印**（A16 上只有协议帧） |
| `"calib"` | 标定阈值 | 只每秒打印 LAB，不理单片机 |

## 三、怎么跑（接单片机）

```
MaixCAM                    STM32F407
A16 (TX)  ───────────────►  PA3  (USART2_RX)
A17 (RX)  ◄───────────────  PA2  (USART2_TX)
GND       ─────────────────  GND          ← 必须共地！
供电：机器人 5V 降压模块 → MaixCAM 的 Type-C/USB 供电脚
```

* 波特率 **115200 8N1**（两端一致）
* 若改用 UART1（A19=TX / A18=RX）：把 `UART_DEVICE` 改成 `"/dev/ttyS1"`，引脚映射代码会自动设
* 比赛时不接电脑 → 需要**开机自启**（见第六节）

## 四、协议速查（改这里必须同时改 STM32 的 `protocol.c` 和 PC 的 `tools/maix_protocol.py`）

```
AA CA AC BB | 长度(4B 小端) | flags(1B) | cmd(1B) | 正文(nB) | CRC16(2B 小端)
长度 = flags + cmd + 正文 + CRC      CRC16 = CRC16_IBM(flags+cmd+正文)（标准 CRC-16/ARC）
```

| cmd | 方向 | 含义 | 正文 |
| :--- | :--- | :--- | :--- |
| `0x10` | 单片机 → MaixCAM | 设为颜色模式 | 无 |
| `0x11` | 单片机 → MaixCAM | 设为形状模式 | 无 |
| `0x12` | 单片机 → MaixCAM | 请求识别一次 | 无 |
| `0x01` | MaixCAM → 单片机 | 上报颜色目标 | 颜色(1) + x(2) + y(2) + w(2) + h(2) |
| `0x02` | MaixCAM → 单片机 | 上报形状目标 | 形状(1) + x(2) + y(2) + w(2) + h(2) |
| `0x00` | MaixCAM → 单片机 | 空帧（没找到） | 无 |

* 所有多字节字段**小端**；flags：请求 `0x01`，上报 `0x21`
* 颜色编码 红1/绿2/蓝3；形状编码 圆柱1/圆锥2/腰鼓3
* 坐标以 **640×320** 为基准（单片机按 X 160~480、Y 80~240 判有效范围）
* 测试向量与自检：`python tools\test_maix_protocol.py`（19 项）+ 单片机 `-DSELFTEST=ON`（28 项）

## 五、现场标定流程（换灯光必做）

1. `MODE = "calib"` → MaixVision 推送运行
2. 把球/人质放画面**正中**，看终端每秒打印的一行：
   ```
   [LAB] 中心13x13 RGB=(183,42,38)  LAB=(46.2, 55.3, 38.1)  范围 L 44~49 A 52~58 B 35~41
          当前阈值 红(1) 命中这块区域 [11, 68, 29, 75, 21, 33]
   ```
3. 照这行数字改 `COLOR_LAB`（建议用"范围"再各留 5~10 的余量，例如范围 A 52~58 → 阈值 A 45~65）
4. 三个色都标一遍；白色形状不用标颜色阈值，但**要确认二值化干净**（`WHITE_GRAY_THR`）
5. 改回 `MODE = "both"`（联调）或 `"protocol"`（比赛）再推送

### 形状判据（重要，已有实测结论）

每次识别都会打印宽度剖面，例如：
```
[形状] 312x300 剖面 w_top=118.2 w_mid=120.5 w_bot=119.0 -> 圆柱  (to_bytes)
```

判别规则：`w_mid` 明显比上下都宽 → 腰鼓；`w_bot` 明显比 `w_top` 宽 → 圆锥；否则圆柱。

⚠ **实测发现**：只用"绝对 50 像素"判据时，**真实尺寸比例的圆锥会被判成圆柱**
（圆锥上 30mm→下 50mm，顶部/底部 20% 区域的平均宽度差只有约 40px，达不到 50px）。
所以默认用 `SHAPE_RULE = "either"`：**绝对或相对满足一个就算**，对远近都不敏感。
想改回单一判据就设 `"absolute"` 或 `"relative"`。

## 六、比赛时的独立运行（不接电脑）

1. **供电**：机器人 5V 降压 → MaixCAM 供电；**GND 与单片机共地**（最高频的坑）
2. **开机自启**：MaixVision 里把脚本推送到设备并设为自启动（或用设备上的"应用/开机启动"设置），
   上电后应自动开始跑；`MODE = "protocol"` 时它是静音的，看不出"在不在跑"，
   可以先用 `"both"` 跑一次、看到每秒的 LAB 打印就说明活着，再切回 `"protocol"` 比赛
3. **验证在跑**：让单片机发一次 `0x12`，如果 S3 的绿灯闪一下后亮起对应颜色灯 → 它活着且在正常工作

```powershell
python tools\test_main_v3.py      # 21 项：协议逐字节一致 / 颜色 / 形状 / LAB / MODE 行为
```

真机上仍需确认的三件事：`find_blobs` 的关键字参数、`to_bytes` 是否可用（不可用会自动退回 `get_pixel`）、
以及**三组 LAB 阈值在你的灯光下是否命中**（这个只能上真机标）。

## 八、给队友的接口约定（一句话版）

> 你（STM32）在 S3/S6 发 `0x10` 切颜色模式、S9 发 `0x11` 切形状模式，每次要识别就发 `0x12`；
> 我最多 300ms 内回一帧：`0x01`/`0x02` 带"编号 + x/y/w/h"，没找到回 `0x00`。
> 匹配、范围判断、重试（3 次后跳过）都由你负责；我只负责"看到什么就报什么"。
