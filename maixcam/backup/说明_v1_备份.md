## v1 做了什么

* **完全被动**：不主动拍图/识别/上报；收到 STM32 命令才动。
  * `0x10` → 模式 = 颜色；`0x11` → 模式 = 形状；`0x12` → 拍一帧、识别一次、上报一帧。
* **颜色识别**：`find_blobs` + LAB 阈值（红/绿/蓝三组已写死在文件顶部），取面积最大的色块，上报编号 + 原始坐标。
* **形状识别**：转灰度 → 按行二值化 → 宽度剖面（顶 20% / 中 50% / 底 20%）→ 判别圆柱/圆锥/腰鼓。
  * 用 `bytes.translate` + `find/rfind` 做逐行扫描（C 速度），不依赖 numpy / find_blobs。
* **协议**：`AA CA AC BB` + 长度(4B LE) + flags + cmd + body + CRC16(IBM, 2B LE)，
  自带解析状态机和 CRC，和 PC 端 `tools/maix_protocol.py`、STM32 端 `protocol.c` 三方一致。
* **UART**：UART0 `/dev/ttyS0`（A16/A17），115200 8N1；也支持 UART1 `/dev/ttyS1` 并自动做 pinmap。

## 已知的 API 不确定性（v1 里已经做了兼容，但要在真机上验证）

| 点 | 处理方式 |
| :--- | :--- |
| `blob` 是"下标访问"还是"方法/属性" | 两种都兼容（`blob[0..3]` 优先，其次 `blob.x()`） |
| `image.Format.FMT_GRAYSCALE` 名称可能不同 | 依次尝试 `FMT_GRAYSCALE / FMT_GRAY / FMT_GRAY8`，再退到 `to_grayscale()` |
| `Image.to_bytes()` 是否需要参数 | 先无参调用，`TypeError` 时带 `"grayscale"` 再试 |
| `to_bytes()` 的行跨距（stride）是否有填充 | 用 `len(data)//h` 反推 stride |

> 这些兼容都是"猜"出来的兜底，**必须在真机 MaixVision 里跑一次确认**，新版本要把它做实。

## 什么时候用它

等 STM32 与 MaixCAM 的串口（A16/A17 ↔ PA2/PA3）接好、要联调整机时，
把 `main_v1_stm32_uart.py` 复制回 `main.py` 即可（或改名成要跑的文件）。
