# MaixCAM 端开发记录（v2 · 纯打印测试版）

> v1（接 STM32 串口协议版）已备份到 `backup/`，见 `backup/说明_v1_备份.md`。
> 本文件记录 v2 的需求确认（问答）与开发过程。

## 背景与目标（2026-09-17）

* 现状：**MaixCAM 只能通过 USB 连电脑**（用 MaixVision 在线运行），
  与 STM32 的串口还没接（计划 A16/A17 ↔ PA2/PA3）。
* 所以 v2 的目标是：**先在 MaixCAM 端自己把视觉调通**，
  用"打印 + 屏幕显示"的方式把识别到的信息呈现出来，方便对着真实物体看效果。
* 暂时**不需要**：UART 协议、STM32 交互、被动等待 `0x12`。

| # | 问题 | 结论 |
| :- | :--- | :--- |
| 1 | 在 MaixCAM 上先测什么目标？ | ✅ **只测小球（排爆物球体）的颜色识别**——最小闭环：读图 → find_blobs 找色块 → 打印 + 画框；形状识别后面再加 |

| 3 | 打印到哪里？ | ✅ **两者都要**：MaixVision 终端打印数值 + 屏幕上画框并写颜色名 |

| 8 | 打印节奏？ | ✅ **只在结果变化时打**：①有球↔无球切换 ②颜色变化 ③中心点移动 > `PRINT_MOVE_PX`(20px)；位移打印再加"间隔 ≥ `PRINT_MIN_INTERVAL_MS`(1000ms)"兜底限流，状态切换不受限 |
| 9 | v2 要不要带 v1 的串口协议？ | ✅ **完全独立**，不带 UART/协议代码；将来联调直接跑 `backup/main_v1_stm32_uart.py` |

## 第二轮问答（真机试跑后新增需求）

| # | 问题 | 结论 |
| :- | :--- | :--- |
| R1 | "距离限定"用哪种方式实现？（MaixCAM-Pro **板载无 ToF**，官方 ToF 是外接 OPNS303x 模块） | ✅ **只用像素大小反推距离**（2026-09-17）：`距离 d = K / 像素宽度 w`，需要现场做一次标定得到 K；并打印 cm 数 |
| R2 | 距离限定接受哪个范围（比赛识别距离约 10cm）？ | ✅ **5~15cm**（2026-09-17）；超出范围时打印提示（如"最近候选 20.0cm 超范围"），方便判断是"没找到"还是"太远被排掉" |
| R3 | 屏幕上问号怎么改？（默认字体只支持英文，中文要用内置 `SourceHanSansCN-Regular.otf`） | ✅ **改成数字形式**（2026-09-17）：屏幕上显示 `1 x300 y140 w60 h60`（= 颜色编号 + 包围盒，与将来发给 STM32 串口 body 的字段顺序一致，纯 ASCII 不依赖字体）；**终端保留中文+数字**（真机已验证终端能正常显示 UTF-8 中文） |
| R4 | 距离标定值（球放 10cm 时 w 是多少像素）怎么给我？ | ✅ **先跑一次报 w**（2026-09-17）：代码里 `CALIB_WIDTH_PX = 0` 表示未标定，此时**不卡距离**、只打印 w 和提示；用户把球放 10cm 处读到 w 后填进常量（或告诉我）即可 |

### 第二轮实现（已写进 `maixcam/ball_test.py`）

| 项 | 做法 |
| :--- | :--- |
| 距离公式 | `d = K / w`，`K = CALIB_DISTANCE_CM × CALIB_WIDTH_PX`（标定后 K 固定；球径多大都行，K 会把真实尺寸吸收掉） |
| 环境常量 | `CALIB_DISTANCE_CM=10.0`、`CALIB_WIDTH_PX=0`（未标定）、`DIST_MIN_CM=5.0`、`DIST_MAX_CM=15.0` |
| 未标定时 | 不做距离过滤，banner 打印提示"把球放到 10cm 处读 w"；每行结果里 `距离≈` 不显示 |
| 标定后 | 每行结果追加 `距离≈9.7cm`；超出范围直接判为不合格 |
| 超范围的提示 | 未找到时打印 `(最近候选 20.0cm, 超出 5~15cm)`，一眼区分"没识别到"和"太远被排掉" |
| 屏幕标签 | 改成 `1 x300 y140 w60 h60`（= 串口 body 字段顺序），纯 ASCII，不再出现问号；**终端仍保留中文** |
| 过滤顺序 | 先形状（面积/长宽比/饱满度）→ 再距离；两者都被拒时原因都记在 `rejects` 里 |

## 实现说明（`maixcam/ball_test.py`）

| 项 | 做法 |
| :--- | :--- |
| 检测 | `img.find_blobs([LAB阈值], area_threshold=100, pixels_threshold=100, merge=True)`，整幅画面 |
| 圆度筛选 | ①面积 ≥ `MIN_AREA`(100px) ②长宽比 `w/h` ∈ [`ASPECT_MIN`0.70, `ASPECT_MAX`1.40] ③饱满度 `pixels/(w*h)` ∈ [`FILL_MIN`0.50, `FILL_MAX`0.92]（圆的理想值 ≈ π/4 = 0.785，实心方块 ≈ 1.0 会被卡掉） |
| 取哪个 | 通过筛选的候选中取**像素最多**的那个 |
| 打印 | `[  1.20s] 红(1) x=300 y=140 w=60 h=60`；位移打印时追加 `(中心 361,179)`；丢球打 `未找到红球` |
| 屏幕 | `draw_rect` 画绿框 + `draw_string` 写 `红 60x60` |
| 多色独立状态 | 每种颜色一套打印状态（`self.st[cid]`），所以开 `ALL_COLORS=True` 时三种颜色互不干扰 |
| API 兼容 | `blob[0..3]` 与 `blob.x()` 两种写法都支持；`pixels()`/下标 4/`w*h` 三级兜底 |
| 可调参数 | 全在文件顶部配置区；`SHOW_REJECT=True` 会把被过滤掉的候选及原因一起打出来（调过滤参数时用） |

### 调参提示

* 球**找不到** → 阈值太窄（补标定模式）或 `MIN_AREA` 太大
* **误识别**到处是 → 阈值太宽；`SHOW_REJECT=True` 看是哪些候选混进来了
* 球**有时找到有时丢** → `FILL_MIN` 偏紧（球被遮挡/反光导致填充率下降）

## 验证结果

电脑上不需要真机即可验证逻辑：伪造 `maix` 模块（camera/display/image/app）+ 脚本化的候选项，
共 **27 项测试**全部通过：

```powershell
python tools\test_ball_test.py
```

覆盖：
* 圆球通过；**实心方块被"饱满度"拒**；细长条被"长宽比"拒；噪点被"面积"拒
* 多候选时取像素最多者；略微椭圆(1.2)仍通过；只测红色时绿球不被误报
* 打印策略：首次找到打 / 不动不打 / 小位移不打 / 大位移且过间隔才打 / **限流期内不刷** / 丢球立刻打 / 持续无球不重复打 / 重新找到再打
* `ALL_COLORS=True` 三种颜色状态互不串扰
* **距离**：未标定不过滤；`d=K/w` 数值正确；范围内通过；太远/太近被拒；边界 5/15cm 通过；
  "未找到"时给出 `最近候选 20.0cm, 超出 5~15cm`
* **屏幕标签**：数字形式 `1 x300 y140 w60 h60`、纯 ASCII（防止再出现问号）
* 整条 `run()` 循环（假相机喂 3 帧）输出符合预期

> ⚠ 真机上仍需确认的（电脑测不到）：`find_blobs` 关键字参数名、
> `draw_string` 签名、相机实际分辨率与视野、以及**红色阈值在你的灯光下是否命中**。

## 运行方式

1. USB 线连 MaixCAM 与电脑，打开 MaixVision。
2. 打开 `maixcam/ball_test.py`，点运行 → 代码推送到设备执行。
3. MaixVision 下方终端看打印；MaixCAM 屏幕看识别框与文字。
