# 联调与现场调试手册

## 一、灯效对照表（占位实现，一眼看出现场在干什么）

### 三色 LED（PD12 红 / PD13 绿 / PD14 蓝）

| 状态机动作 | 灯效 |
| :--- | :--- |
| 前进 | 红 + 绿 一起闪（500 ms） |
| 后退 | 绿 + 蓝 一起闪（500 ms） |
| 左转 | 红 + 蓝 一起闪（500 ms） |
| 右转 | 红 + 绿 + 蓝 一起闪（500 ms） |
| 停止 | 全灭 |
| 机械臂移到识别位 | **蓝灯常亮 500 ms** |
| 等 MaixCAM 上报 | **绿灯慢闪（500 ms）** |
| 抓红色 / 圆柱形 | 红灯常亮 500 ms |
| 抓绿色 / 圆锥形 | 绿灯常亮 500 ms |
| 抓蓝色 / 腰鼓形 | 蓝灯常亮 500 ms |
| 激光开启 | 红灯闪（500 ms） |
| 激光关闭 | 熄灭 |
| 出错卡死（Error_Handler） | 红灯极快闪（约 10 Hz） |

### 心跳灯（PB0，独立）

| 状态 | 灯效 |
| :--- | :--- |
| 正常运行 | 每 500 ms 翻转 |
| S12 任务完成 | 常亮 |
| 程序跑飞 / 死循环在内核异常 | 停住不动（HeartFault 里 while(1)，心跳会停） |

> 心跳灯是判断"程序还活着"最直观的办法：只要它在闪，主循环就在正常转。

## 二、分步联调流程（强烈建议按顺序做）

### 第 0 步：只烧固件，看心跳

```powershell
cd D:\stm32ideproject\AntiTerrorRobot
.\build.ps1 ; .\flash.ps1
```

* PB0 心跳灯 500 ms 闪 → 时钟、HAL、主循环都正常。
* 接下来三色灯会开始按状态机跑（前进 1 s → 蓝灯常亮 → 绿灯慢闪 …）。

### 第 1 步：验证协议逻辑（不需要任何外设）

```powershell
.\build.ps1 -SelfTest ; .\flash.ps1 -Config SelfTest
# USB-TTL: TX→PA9, GND→GND, 115200 8N1, 串口监视器编码选 UTF-8
```

上电应打印：

```
******** 自检开始 v1.0 ********
[1] CRC16_IBM
  [PASS] crc16("123456789") == 0xBB3D
  ...
******** 自检结果: 28 项通过, 0 项失败 ********
******** 全部通过, 可以开始跑任务 ********
```

有 FAIL 说明固件逻辑被人改坏了，先修再往下走。

### 第 2 步：用 PC 模拟 MaixCAM，把状态机跑通

```powershell
python tools\maix_sim.py --list                 # 找到接 USART2 的那个串口
python tools\maix_sim.py --port COM5
```

USB-TTL 的 TX 接 STM32 **PA3(USART2_RX)**，RX 接 PA2，GND 共地，115200。

你会看到 PC 端打印：

```
[收] 设为颜色模式  AA CA AC BB 04 00 00 00 01 10 00 5C
     模式 = 颜色
[收] 请求识别一次  AA CA AC BB 04 00 00 00 01 12 81 9D
     第 1 次识别请求 (模式=color), 处理中...
    -> 回复 排爆物/红 id=1 x=208 y=145 w=44 h=56
```

同时 STM32 的调试串口（PA9）会打印 `[VIS] cmd=0x01 id=1 x=208 y=145 ... OK`
→ 说明 **S3 整条链路（发命令 → 收帧 → CRC → 匹配 → 范围判断 → 进 S4）全通**。

### 第 3 步：故意制造故障，验证重试与跳过

```powershell
# 一半概率发错, 看 STM32 是否原地重试 3 次后跳过
python tools\maix_sim.py --port COM5 --fail-rate 0.5

# 全部回 CRC 错的帧 → 应该 3 次后跳过
python tools\maix_sim.py --port COM5 --crc-error-rate 1.0

# 全部回空帧 → 应该 3 次后跳过
python tools\maix_sim.py --port COM5 --empty-rate 1.0

# 全部回超范围坐标 → 应该 3 次后跳过
python tools\maix_sim.py --port COM5 --out-of-range-rate 1.0

# 每次拖 500ms 才回 (> 300ms 超时) → 应该重试后跳过
python tools\maix_sim.py --port COM5 --delay-ms 500
```

期望行为（看 PA9 日志）：

```
[VIS] 重试第 1 次
[VIS] 重试第 2 次
[VIS] 重试 3 次失败, 跳过本任务
[S3] 跳过排爆, 直接去反恐区
```

而且**整个过程不卡死**，后面 S5/S6/S7… 继续往下走。

### 第 4 步：接真 MaixCAM

1. 把 `maixcam/main.py` 用 MaixVision 推到 MaixCAM 上运行（或设为开机自启）。
2. 接线：MaixCAM A16(TX) → STM32 PA3，A17(RX) → STM32 PA2，GND 共地。
3. 先用 MaixCAM 自己的屏幕看画面，调整机械臂识别姿态，让目标落在画面正中。
4. 标定阈值（见下面第三节），标完再联调。

### 第 5 步：接真实执行机构

按 `README.md` 第七节，把 `motion.c` / `arm.c` 里的占位函数换成真驱动。
状态机不用改。改完先单独测每个动作，再整段跑。

## 三、现场必须标定的参数

| 参数 | 文件 | 位置 | 怎么标 |
| :--- | :--- | :--- | :--- |
| 三色 LAB 阈值 | `maixcam/main.py` | `COLOR_THRESHOLDS` | 把物体放识别位，看 MaixVision 图像调试里的 LAB 值，卡上下限 |
| 白色灰度阈值 | `maixcam/main.py` | `WHITE_GRAY_THR`（暂 200） | 白 PLA 与黑台面之间取中间值 |
| 形状判别像素差 | `maixcam/main.py` | `SHAPE_WIDTH_DIFF`（暂 50） | 三个形状各测一遍 w_top/w_mid/w_bottom，取能分开的最小值 |
| 视觉有效范围 | `firmware/Core/Inc/app_config.h` | `VISION_X_MIN` 等 | 若机械臂姿态导致目标偏离中心，放宽/收紧 |
| 视觉超时 | 同上 | `VISION_TIMEOUT_MS`（300） | MaixCAM 识别慢就加大 |
| 重试次数 | 同上 | `VISION_RETRY_MAX`（3） | 按裁判节奏调 |
| 动作时长 | 同上 | `MOTION_MS` / `ARM_*_MS` / `LASER_ON_MS` | 接真机构后按机械实际速度调 |
| 二维码占位值 | 同上 | `QR_PLACEHOLDER_*` | 不扫码联调时改这里 |

> ⚠ 比赛现场灯光一变，颜色阈值几乎必然要重标。**留 10 分钟标定时间**。

## 四、常见故障排查

| 现象 | 原因 | 处理 |
| :--- | :--- | :--- |
| CLion 点 Run 报 `error=193, 不是有效的 Win32 应用程序` | 这是 ARM 固件，Windows 执行不了 `.elf` | **不是代码问题**（说明已编译成功）。用 `Build` 编译，用 `.\flash.ps1` 烧录；要调试用 `.\debug.ps1 -Gdb`。顺手把 CLion 自动建的 `AntiTerrorRobot` 运行配置删掉即可，详见 README 2.2 |
| CLion 里 `.ps1` 脚本的参数不生效（例如传了 `-Stop` 没反应） | Windows PowerShell 5.1 用 GBK 读 UTF-8 脚本，中文注释会把 `param` 块解析坏 | 这几个脚本我都保持纯 ASCII；你自己改脚本时**别在 `param` 块附近加中文注释**，或把文件存成带 BOM 的 UTF-8 |
| CLion 运行 Shell Script 配置报 **「错误: 找不到解释器」** | Interpreter path 只写了 `powershell.exe`，而 CLion **不查 PATH** | 填绝对路径 `C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe`（换机器先 `where powershell`）。此时 `debug.ps1` 根本没被执行，ST-LINK_gdbserver 自然起不来——**与 ST-Link V2 硬件无关**，别去折腾烧录器 |
| CLion 的 ST-LINK 配置提示找不到探头 | ST-Link V2 没插 / 驱动没装 / 板子没上电 | 设备管理器里应能看到 `STM32 STLink`；先用 `.\check_stlink.ps1` 自检，再回 CLion 调试 |
| `flash.ps1` / `check_stlink.ps1` 报 `DEV_CONNECT_ERR` 或 `No STM32 target found` | **同一个 ST-Link 只能被一个程序用** | 先 `.\debug.ps1 -Stop` 关掉 GDB server，并停止 CLion 的调试会话；再不行按自检脚本提示查 GND / SWDIO(PA13) / SWCLK(PA14) / 板子供电 / 降频 `-FreqKHz 500` |
| 回读校验时 `.bin` 与芯片差几个字节（`0x00` vs `0xFF`） | `objcopy` 给链接对齐空洞补 `0x00`，flash 擦除值是 `0xFF`，`.hex` 里不包含这些地址 | **正常现象，不是烧录失败**。以 `.hex` 为准：`python tools\verify_flash.py 固件.hex 回读.bin --diff-bin 固件.bin` 会把这部分单独统计（本项目实测正好 8 字节） |
| 想知道"程序跑到哪一步了" | —— | 用 GDB 直接读全局变量：`state` / `retry_count` / `qr_done` / `g_maix_tx_frames`（见 README 2.2 第 7 条） |
| 心跳灯不闪 | 程序没跑起来 / 时钟配置失败 | 检查 HSE 晶振频率是否 8 MHz（25 MHz 板要改 `HSE_VALUE` + `PLLM`） |
| 红灯极快闪 | `Error_Handler()` | 看是哪一步 `HAL_*_Init` 失败了，通常是晶振起不来 |
| 串口日志乱码 | 波特率或编码不对 | PA9 → USB-TTL，115200 8N1，**串口监视器编码选 UTF-8** |
| **USART1 收不到二维码** | 接线 / 波特率 / 共地 | GM65 默认 9600 8N1；确认 GM65 的 TX → PA10，共地 |
| 二维码读到但一直不匹配 | 码值超出 1~3 范围 | GM65 输出必须是三位 1~3 的数字；带前缀也可以（解析会跳过非数字） |
| **MaixCAM 一直没上报** | 见下面专项 |
| 日志里 `[VIS] 重试 3 次失败` | 视觉没对准 / 阈值不对 / 编号对不上 | 先看 `[VIS] cmd=... id=...` 那行，判断是"没找到"还是"找到了但编号不对" |
| 状态机卡在某个 S | 理论上不会（全部用 tick 判超时） | 若真卡住，看心跳灯是否还在闪；不闪就是死循环，用调试器看调用栈 |

### MaixCAM 没上报专项排查

1. **MaixCAM 的屏幕/串口有没有打印**收到命令？没有 → STM32 没发出去或线接反
   （TX/RX 要交叉：STM32 PA2 → MaixCAM A17，MaixCAM A16 → STM32 PA3）。
2. **有没有回帧**？用逻辑分析仪或 USB-TTL 并在 PA3 上看有没有 `AA CA AC BB`。
3. **CRC 一直错**？`g_maix_crc_err` 在自检/调试里可以打印；两端 CRC 实现必须都是
   `CRC16_IBM` + **小端序**写入。用 `python tools\test_maix_protocol.py` 对一下向量。
4. **模式不对**：MaixCAM 收到的 `0x10`/`0x11` 顺序错了（S6 不再重发模式命令，
   靠 S3 那次设置记住；如果中途复位过 MaixCAM，模式会丢 → 看它的日志）。

## 五、比赛前一天检查清单

- [ ] `.\build.ps1` 通过、0 warning，烧录的是**最新**固件（不是 SelfTest 版）

- [ ] 二维码用真码测一遍（三位数字 1~3），`[S1] 二维码 xyz` 日志正确
- [ ] 断电重上电（一键启动）→ 全流程自动跑完，最后心跳灯常亮 3 s 后回到 S0

- [ ] 备用电池 / 备用 USB-TTL / 备用杜邦线
- [ ] MaixCAM 设为**开机自启**（否则重新上电后没人点运行）

## 六、串口日志速查（PA9，115200，UTF-8）

| 日志 | 含义 |
| :--- | :--- |
| `===== S0 初始化 (第 N 轮) =====` | 每轮任务开始 |
| `[S1] 二维码 213 -> 排爆:绿 靶:红 人质:腰鼓` | 读到码并解析成功 |
| `[S1] 读码超时 3000ms, 使用占位值 112` | 没读到，用占位值继续 |
| `[MOTOR] 前进 / 后退 / 左转 / 右转` | 底盘动作 |
| `[VIS] cmd=0x01 id=2 x=300 y=140 w=60 h=60 OK` | 一帧视觉数据 + 判定结果 |
| `[VIS] 重试第 1 次` | 该环节重试 |
| `[VIS] 重试 3 次失败, 跳过本任务` | 该环节放弃，进下一状态 |
| `[S3] 找到排爆物: 红` / `[S4] 放入排爆桶` | 任务节点 |
| `[S7] 激光开启, 瞄准 红 靶心` | 打靶 |
| `[S12] 任务完成, 停留 3000ms 后重新开始` | 一轮结束 |
